Indexed Search

Speed up repeat searches with a background index.

FileSearch has folder content indexes for repeat text and mail searches, plus whole-drive name indexes for local NTFS drives. The desktop app can keep indexes current in the background.

Folder Content Indexes

  • You choose folders to index, called indexed locations. FileSearch scans them in the background and stores their text in a local database.
  • When Keep index updated after closing window is enabled, closing the main window hides FileSearch to the tray so indexing and Quick Search remain available.
  • A file watcher batches changes inside indexed locations while either the GUI or tray indexer is running. Local NTFS roots can also catch up from USN journal checkpoints after FileSearch restarts.
  • A content search uses the index when it is covered: the folder in the search bar falls inside an indexed location and the current options match what was indexed. When a search is not covered, FileSearch automatically falls back to a normal live scan.
Indexed search is opt-in. Turn on Use index in search options, or Use index for covered searches in the Manage indexed locations window. Searches outside content-index coverage fall back to a live scan. Allow pending index updates to finish when files have recently changed.

With document extraction enabled, a folder content index includes local MSG messages and individual messages from PST/OST stores, as well as EML. Changed stores are extracted in full; per-message incremental updates are not available. See Outlook Mail Search.

When an indexed location is built with Image OCR enabled, the index can include recognized text from standalone image files, scanned PDF pages, and embedded images in Office, OpenDocument, EPUB, EML, and ZIP/archive files. MSG/PST/OST attachment OCR is not supported. OCR hits keep source labels such as page, member path, and OCR region when that information is available.

If a location was indexed before Image OCR was enabled, scanned PDF text will not appear in indexed results until you use Rebuild selected for that location.

Managing Indexed Locations

For meaning-based text search, install a Smart Search model and use the selected location's Smart Search > Rebuild Smart Search action to build vectors from its indexed content. Refresh status reports coverage. See Smart Search with ONNX for the full walkthrough.

Open Index > Manage indexed locations..., or choose Manage locations in the sidebar's Indexed locations section.

Startup Catch-Up

When FileSearch starts, it loads pending changes, starts watchers for configured roots, then chooses the safest catch-up strategy for each location.

  • Local NTFS uses USN journal replay when a valid checkpoint is available.
  • ReFS, FAT/exFAT, cloud folders, and removable drives use snapshot scans plus watcher updates when available.
  • Network shares use scheduled snapshot scans. Watcher events are treated as best effort.
  • Unavailable drives keep cached index entries and show as offline until the folder is reachable again.

USN replay falls back to a snapshot scan when the journal was recreated, the saved checkpoint expired, access is denied, a changed path cannot be resolved, or a known-file delete could be ambiguous because of hard links. ReFS durable replay is deferred until FileSearch supports 128-bit ReFS file identifiers.

Location Details

Selecting a location shows its current state:

  • Status, Files, and Lines show how much of the location is indexed.
  • Refresh shows when the location was last indexed.
  • Coverage shows whether subfolders are included or only the top folder.
  • Watcher shows whether file changes are applied automatically.
  • Indexed with records the extraction options used, such as whether Office/PDF documents and image OCR were included and whether unknown file types were skipped.

Drive File-Name Index

A drive index stores file and folder names across a local fixed NTFS drive. It does not store document or mail content. Enable a drive under File > Settings > Drive file-name index and check its status there.

Build methodBehavior
Use fast administrator scanReads the NTFS master file table. An unelevated app asks Windows to start a one-time elevated helper; it writes a snapshot and exits. Declining the prompt falls back to the folder scan.
Folder scanReads names and file IDs without elevation. It is slower and skips folders the current user cannot read.
RebuildBuilds the selected drive again with the chosen method. Missing indexes for enabled drives are built automatically at startup using the folder scan, without a UAC prompt.

The running desktop app applies USN change-journal updates and saves changed snapshots periodically and on exit. Expired or recreated journals require a rebuild and trigger a folder scan. A drive without a change journal can be indexed, but it does not update live.

  • Quick Search uses drive names for its Entire machine metadata scope and for covered folder scopes. Drives without an index use a bounded live metadata scan, which may be incomplete.
  • Main-window and CLI name searches use the drive index with Use index or --index when all roots are covered. Current name filters still apply; unsupported traversal cases fall back to a live walk.
  • Content searches, including mail bodies, use folder content indexes or live extraction.

Only local fixed NTFS drives are supported. A hard-linked file is indexed under one name. File-name searches that could traverse directory links can fall back to a live scan. Even after an administrator build, new or renamed entries in unreadable folders may not be fully tracked by the unelevated app. Store/MSIX restrictions may require the folder scan.

See Drive Name Commands for terminal builds and searches. The CLI loads snapshots and catches up from the journal in memory; it does not continuously track drives or save updated snapshots except when building.

Where Indexes Are Stored

The folder content database is under %LocalAppData%\FileSearch\Index. It contains local searchable text and metadata from your indexed locations, including mail. Removing a location deletes its indexed data.

Drive name snapshots are separate files under %LocalAppData%\FileSearch\Index\Volumes\Volume{GUID}.fsvol. Disable a drive in Settings or use volumes remove to remove its name index.

The current database schema supports large file sizes and NTFS journal positions. Existing schema-26 databases upgrade in place on the next write while preserving locations and content. Close older FileSearch processes before using the updated indexer.
