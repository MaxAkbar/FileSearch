Results

Review, refine, and open matching files.

Select a file, folder, or message card to preview its matches. Use the results toolbar to refine, group, or sort the current results, or open items directly from their cards.

Result Cards

The result list shows file, folder, or message cards with matching lines. Only visible cards are rendered, and results arrive in batches while searching. Use the toolbar to choose grouping, sorting, and how many matching lines to show.

Detail Description
Name The matched file or folder name, or the subject of an Outlook message.
Hits The number of matching lines, spans, or name matches found for that result.
First match A short preview of the first matching line.
Location The folder containing the file.

Matching Lines and Context

Select a card to load the preview pane. Content searches show matching line numbers and nearby context; name searches show name-match details. For large or binary-backed document formats, the preview may be simplified depending on the extractor. OCR image hits include the recognized line's image-region label and can show standalone images with the OCR region highlighted. OCR PDF hits include the page and region label and can render the page with the OCR region highlighted. Embedded-image OCR hits from documents, EML, EPUBs, and archives include the member path and OCR-region label; when the embedded image can be read from the parent file, preview extracts it and highlights the OCR region.

Use Open OCR preview on OCR-backed results to open a dedicated FileSearch preview window at the exact highlighted region. The normal Open action now tries the best available source target first: OCR region preview for OCR hits, a PDF page link for page-anchored PDF hits, or a line-and-column editor target when Visual Studio Code is installed. If no exact target is available, FileSearch opens the parent file in its default app.

Mail Messages

Each matching PST/OST message has a separate card with subject, sender, date, and mail folder. Preview and Copy file content read only that message. Open creates a text-only EML copy in the registered mail app; opening MSG uses the original file's registered app. Individual store messages cannot be renamed, deleted, pinned, favorited, or dragged as files. Copy path and Reveal refer to the store. See Mail Results and Preview.

Search Statistics

The results toolbar and status bar show match counts, elapsed time, and live progress. Individual store messages count as separate result items. Workflow file counts refer to physical files and count their containing stores instead.

The main window retains up to 100,000 hits. Further hits are counted but not displayed; the status reports when only the first hits are shown. Narrow the search to review more of a large result set.

Refine Current Results

Filter current results narrows the files, folders, or messages already returned by the main search. Enter exact text to match a displayed name, file/folder path, or returned match excerpt. Matching ignores case; spaces form one phrase, and AND or OR are treated as literal text in this box.

  • Results update as you type. The box filters the returned names, paths, and excerpts; use the main search to search complete file contents or find additional files.
  • Filter matches are highlighted in card names, paths, folder-group headings, and the Matches preview. Original search highlights remain visible. Cards bring matching excerpts forward, including lines beyond the first three.
  • Opening a filtered card uses its matching source hit when available. Clearing the filter restores the original excerpts and original search highlights.
  • Whole-file File preview is a separate viewer; this box does not search or highlight every occurrence throughout that document.
  • Run a new search when you need to change folder, file pattern, query mode, or date and size filters.

Sorting, Grouping, and Facets

The toolbar beside the match count reorganizes the current result set without scanning files again.

  • The filter results box keeps only cards whose name or matching lines contain the text.
  • View groups cards (by folder by default, or by type, date, source, or not at all), sorts them by relevance, name, modified date, size, hits, or type, and switches between showing matching lines and one line per file. Folder groups collapse with their arrow.
  • Filters opens the facet bar.
  • Type, Folder, Date, Source, and Size facets narrow the visible result cards. Source shows whether the result came from the index or a live scan.
  • The clear button beside the facet controls resets all result facets.

Opening and Copying

Double-click a result row to open the file or folder. Right-click a row for more actions:

  • Open opens databases in FileSearch's built-in read-only viewer. For other files, it opens the exact source location when FileSearch can represent one, otherwise uses the default Windows application or opens the folder in Explorer. If Windows cannot open a file, FileSearch shows a message.
  • Open OCR preview opens FileSearch's exact highlighted OCR preview when the result has an image, scanned-PDF-page, or embedded-image OCR region.
  • Reveal in Explorer opens the containing folder and selects the file, or opens the folder itself.
  • Rename changes a file name in the same folder. Folder rename is not enabled from search results.
  • Move to Recycle Bin asks for confirmation before deleting a file and uses the Windows Recycle Bin.
  • Copy file path copies the full result path to the clipboard.
  • Copy folder path copies the containing folder path.
  • Add favorite saves the file in the Favorites sidebar section.
  • Pin result keeps the file available in Quick Search when no query is typed.
  • Drag a result card to another app or folder to start a Windows file drag-and-drop operation.

The Preview Pane

Use the Matches tab for search-hit context, or File preview to view the original file. File previews also work for filename-only results and do not require PowerToys.

File Preview

  • Images: preview PNG, JPEG, BMP, WebP, GIF, TIFF, ICO, and SVG files. Raster images support Fit and zoom. Animated GIFs play automatically; use Pause animation to inspect a frame, or the arrows to step through frames. Multipage TIFFs have page arrows. Raster frames above 50 megapixels use the fallback preview.
  • PDF: view the whole original page, including when the search hit contains only a short passage or OCR region. Preview starts at the current match's page when a page location is available; otherwise it starts at page 1. Use the arrows to change pages, Fit to see the whole page, or zoom for detail. Expand keeps the page you are viewing. The Matches tab continues to show excerpts and context.
  • Markdown: read formatted headings, lists, and tables. Document scripts, external links, and remote resources are blocked.
  • Source and text: read the original text with line numbers and syntax highlighting for recognized languages. HTML source is shown as text.
  • Spreadsheets: CSV, TSV, XLSX, and ODS use a read-only grid. XLSX and ODS include a worksheet selector. The matching sheet and cell are selected when a location is available. Use Go to cell (for example, AZ501), row and column buttons, or scrolling to explore. The grid loads 250 rows and 40 columns at a time; all supported rows and columns remain accessible. Stored values and cached formula results are displayed; formulas, macros, and external links are never run or refreshed.
  • ZIP archives: select a member to preview its actual text, image, PDF pages, or other supported content. New searches automatically select the matching member. Members are read into temporary preview copies and removed when the preview closes; source archives remain unchanged. Unsafe entry paths, oversized members, and excessive expansion are rejected. Nested ZIP previews stop after three levels. This viewer does not expand which member formats the search extractor indexes.
  • Mail: EML, MSG, and selected PST/OST messages show complete headers, formatted or plain body, and attachment names. This view loads the selected message independently of its search excerpt. EML inline images are supported. Scripts, external links, remote images, and remote resources are blocked; attachments are listed without being opened. Outlook is not required.
  • Books and documents: EPUB shows a whole chapter with chapter selection and local embedded images. ODT and RTF show formatted document content; ODP has a slide selector. These are reflowed content views; they do not reproduce exact printed page or slide layouts and do not require Microsoft Office.
  • Other formats: FileSearch can use a Windows preview handler already installed for the file type, including supported Office formats. Availability depends on installed applications. If no visual preview is available, FileSearch shows file details or existing match text.

Choose Expand to open a larger FileSearch preview window. Previews are read-only and load on demand. Image files are limited to 32 MB, PDFs to 100 MB, and text files to 4 MB; long text previews show the first 250,000 characters. Large, unavailable, protected, or unsupported files can still be opened using the normal Open action.

Expanded previews retain the current PDF page, image frame, chapter, slide, archive member, or spreadsheet cell. Refresh an existing index to add precise XLSX-cell and ZIP-member locations to older hits. Without an exact location, the viewer uses available match text or starts at the first part; selectors remain available.

Structured previews are bounded: CSV/TSV and package XML are limited to 32 MB; spreadsheets to one million populated cells; package contents to 10,000 entries; selected ZIP members to 64 MB; and GIF/TIFF to 2,000 frames. Individual EML/MSG files are limited to 64 MB, message bodies to four million characters, RTF to 4 MB, and embedded document images to 32 MB combined. Content exceeding these limits uses the fallback instead of presenting an unlabeled partial document.

Database Search and Preview

SQLite and CSharpDB table contents are searchable from local .db, .sqlite, .sqlite3, .db3, .csharpdb, .csdb, and .cdb files. The engine is detected from the file header. Choose Contents, enable Document & database text, and search normally or use type:database invoice in Unified mode. Refresh existing content indexes to add these values to indexed search and Quick Search.

Hits identify the table, row number, and column. File preview shows the complete supported record around a hit in a read-only grid. Choose a table, use Go to row, or use the page buttons to browse 250-row pages. Columns scroll horizontally. Record keys show SQLite rowid or primary-key values when available; row numbers are snapshot positions. Expand retains the current table, row, column, available record key, and source fingerprint.

Open and Open at line use this viewer in a separate window and retain the matching record when available. Filename-only results, including searches for *.db, start at the first supported table. No default Windows database application is required. Unsupported or unreadable databases show a preview error.

Larger databases can take longer to open because FileSearch first copies the database and its WAL into a private snapshot and reads the table schemas. Snapshot preparation and record loading run in the background. The grid requests 250 records at a time; paging does not remove this initial wait, and jumping far into a table can also take longer.

Find Beyond the Loaded Page

In the database preview, select a table and click the Find in table toolbar button to reveal its controls, or press Ctrl+F while the preview is focused. Enter text, then click the options summary button, initially All terms · All columns ▾, to show matching and column choices. Choose All columns or a specific column, and All terms, Either term, or Phrase. Match case enables case-sensitive matching. Click Find to search; Stop cancels a running scan. Detailed options collapse when Find starts to leave room for records, while the summary keeps the selected mode and column scope visible.

For john smith, All terms requires both words in the same cell, Either term accepts either word, and Phrase matches the literal text john smith. All terms and Either term split the input at whitespace; quote characters and words such as AND or OR are literal text. Enter a Phrase without surrounding quotes. Searching All columns still checks each cell separately; it does not combine values across a record.

Use ‹ Match and Match › to navigate the matching cells. FileSearch loads the correct 250-row page and selects the matching column, including when the match was outside the displayed page. With the database preview focused, Ctrl+F focuses Find, F3 moves forward, and Shift+F3 moves backward. Run Find again after changing its table or settings.

In Quick Search, opening Find gives the database preview more room. Hide Find to restore the compact results-list layout.

Long matching cells display an excerpt beginning at the first match. Hover over the cell for its full bounded value; copying the cell copies that value rather than the Find excerpt. Click Find in table again to hide its controls. After Find finishes, Expand retains its query, options, matching cells, and the open or hidden state of the Find controls and detailed options with the current database location, provided the source remains unchanged.

A Find scan checks at most the first 100,000 rows, 250,000 non-NULL scalar cells (including empty strings), 16 Mi characters, and 1,000 matching cells, with a 15-second time limit. Each cell contributes at most its first 16,384 characters. NULL and binary values are skipped. Find input supports up to 2,048 characters; All terms and Either term accept up to 64 literal terms. The status identifies incomplete coverage, including limits, truncated text, cancellation, or source changes. A partial or cancelled scan does not prove there are no matches in the unchecked text.

Filter current results searches only the names, paths, and hit text already returned by the main search. Find in table searches the selected table in the private snapshot, including unloaded preview pages. To search other tables or databases together, run a new main search. Ordinary database Find needs no SQL, model, OCR, or PowerToys setup. If the database or WAL changes, reopen its preview from a fresh search and refresh the index when needed.

Search and preview use private database/WAL snapshots and leave source files unchanged. Close the database's application or use a stable backup if it is locked or changing. If the database changes after a hit is found, refresh the index or rerun the search before previewing the old location. Private copies under %TEMP%\FileSearchDatabasePreview are removed when their session closes; after a crash, close FileSearch and clear that directory to remove remaining copies.

Coverage is ordinary SQL tables and scalar values. Views, virtual/shadow/system tables, generated SQLite columns, CSharpDB internal tables, binary payloads, and encrypted databases are excluded. NULL and binary cells are blank in the grid. No SQL console, extension loading, database edits, or remote-server access is provided.

Snapshots including WAL data are limited to 256 MB, 256 user tables, and 512 columns per table. The normal search file-size filter defaults to 100 MB. Search stops at 100,000 rows total, 250,000 populated scalar cells, or 16 Mi characters per database; extraction issues report limits reached. Preview supports the first 100,000 rows per table. Cell text is limited to 16,384 characters with an ellipsis and notice; later text is not searched. CSharpDB compatibility follows the bundled 4.6.4 reader.

Match Context

The preview shows the code around each match with line numbers; matching lines are highlighted and skipped stretches are marked. Use the arrows to step between matches, the wrap button to wrap long lines, and Show whole file to load the full text. Open at line opens the file at the current match; double-clicking any line opens it at that line. Select lines and press Ctrl+C to copy them, or use Copy for the path, folder path, preview, or full file content. Hide the pane with its panel button and bring it back from the results toolbar or View > Preview pane.

Favorites and Pins

Favorites are a full-window list for files you want to return to later. Use the Favorites sidebar section to search, open, or remove favorite files. Pins are separate: they appear in Quick Search when the quick search box is empty.

Workspaces

Use Save current workspace in the Workspaces sidebar section to save the current search settings, custom scopes, favorites, Quick Search pins, selected Quick Search indexed roots, and result sort/group/refine state. Selecting a saved workspace restores those settings.

Use the run-on-load button beside a workspace when you want selecting that workspace to immediately run its saved search after the settings are restored. Workspaces without run-on-load enabled restore the setup and wait for you to start the search manually.

Use Import workspace to load a shared workspace JSON file. Use Export workspaces to write all saved workspaces, or the export button beside a workspace to share just that one workspace.

Exporting

Use Export to write the visible retained results to CSV, JSON, JSON Lines, or Markdown. Active filters and facets are respected; hits beyond the display cap are not included. Narrow the search first when you need a complete export of a large result set.

Grounded Answer Drafts

Use Answer to copy an extractive Markdown draft from the visible results. The draft includes cited snippets and source locations only; it does not infer beyond the search evidence. Apply filters and facets first when you want the draft grounded in a narrower result set.

Quick Search Results

Quick Search uses compact result cards with open, reveal, copy, and pin buttons. Keyboard shortcuts are available for the selected row, and physical-file results can be dragged to another app. Individual store messages have the mail action restrictions described above.
