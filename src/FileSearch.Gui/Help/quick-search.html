Quick Search

Search from anywhere.

Quick Search is a small launcher-style window for everyday lookups. It opens over your current work, focuses the search box, streams results as you type, and closes after you act on a result.

Open Quick Search

FileSearch must be running for the global hotkey to work. If Keep index updated after closing window is enabled, closing the main window keeps FileSearch in the tray and the hotkey remains available. The default hotkey is Win+Shift+F.

Hotkey Notes
Win+Shift+F Default Quick Search shortcut.
Alt+Space Optional shortcut. Windows or another app may already use it.
Ctrl+Space Optional shortcut. Some editors and input tools may already use it.

Change the global hotkey and quick-window action shortcuts in File > Settings > Quick Search. Main-window shortcuts are configured separately in File > Settings > Main Window Shortcuts. If a global hotkey is already reserved by Windows or another app, FileSearch reports that it could not register the hotkey. You can also open Quick Search from the FileSearch tray menu.

Search Names or Content

Quick Search looks for filename and path matches as you type. Turn on Content in the quick window to add file-content matches as their indexed/live query returns. Both sources can arrive while the search is running. If an indexed location was built with Image OCR enabled, recognized image, scanned-PDF-page, and embedded document image text can appear in content results too.

Quick Search content matching uses the entire query as one case-insensitive literal substring. john smith matches that phrase; john OR smith includes the word OR, and quote characters are literal too. It does not split content terms into AND/OR expressions. Use the full search window with Unified or Boolean mode for operators and quoted-phrase syntax, or Unified fields such as type:email.

Filename and path matching has its own word-based behavior, described below; it can return a name even when the content does not contain the literal phrase. Indexed MSG/PST/OST messages appear with Content on when the selected folder content index includes document extraction; MSG/PST/OST attachment OCR is not supported.

  • Content on searches file names and paths, plus text and available OCR content within the selected scope. It requests indexed content; route details report indexed/live results and any allowed live fallback when coverage is unavailable or incomplete.
  • Content off searches only file names and paths, which is useful for launcher-style lookup.
  • The Entire machine metadata scope is metadata-only. A folder or indexed-location scope is required for content search.

Choose a Scope

The scope dropdown controls where Quick Search looks. Use indexed scopes for the fastest daily-driver searches.

Scope What it searches
Selected folder The folder shown in the Quick Search folder field. Use the folder button to change it before searching.
Selected indexed locations Only the registered roots checked in the selected-count popup or File > Settings > Quick Search. The checkboxes are shared with main search. An empty selection searches no indexed locations.
All indexed locations Every indexed root configured in Index > Manage indexed locations.
Entire machine metadata Filename and path matches across ready fixed drives. Built NTFS drive indexes supply saved names; drives without an index use a bounded live metadata scan that may be incomplete. Message and document contents are not searched in this scope.

The location notice explains missing or unavailable coverage. Removed selected registrations remain visible as No longer indexed; they are skipped until registered again or unchecked. Offline/inaccessible roots are skipped with a notice, without adding another folder or broadening to all locations. Overlapping roots do not duplicate the same result or source hit.

Enable drive indexing in File > Settings > Drive file-name index. Covered folder scopes also use these names. Every search word must match the entry name or its folders, and at least one must match the entry's own name; a term containing \ must match the full path. See Drive File-Name Index.

Open Full Search Without Changing Intent

Choose Open full search to carry the current query, folder or indexed-location scope, content choice, and selected result into the main window. Main search retains Quick Search matching: every space-separated literal word must match the filename/path, while content must contain the complete literal phrase. Words such as AND and OR, quotes, and regular-expression characters are literal text in this profile.

Full search can return more matches than Quick Search's bounded metadata stage. The Quick matching profile accepts at most 8,192 characters and 256 distinct name/path terms; longer input is rejected explicitly.

The main window explains the retained profile and offers Use standard matching to return to its ordinary query mode. Saved searches and workspaces preserve the scope, selected roots, and profile. Database records, archive members, and message identities remain attached to their source results when available.

Entire-machine metadata stays in Quick Search because main search has no equivalent scope; select a folder or indexed locations before handing off. The action is unavailable while a main-window search or replacement is busy. Opening full search closes an idle replacement panel without applying any changes.

Ranking and Keyboard Selection

Results are ranked as candidates arrive. Exact filenames and exact names without their extension rank ahead of weaker prefix or folder-word matches, even when the exact file is deeper in a folder tree or arrives later. Within the same ranking tier, complete name components separated by punctuation, spaces or case transitions receive a bounded preference over substrings inside longer words. Exact-name and phrase-prefix priorities and literal matching rules stay the same. Name relevance takes priority over different content/index score scales; equal candidates use a deterministic path order.

Until you choose a result, the selection follows the current best match. Navigate results with the keyboard, click a result, or choose Preview to keep that selection while later matches arrive. Changing the query, content choice or search scope starts a new search, clears the prior selection and preview, and prevents actions on stale result rows.

Quick Search displays at most 80 results from bounded candidate discovery. The content-enabled search stage collects at most 80 result identities or 500 unique hits; it can return indexed filename hits as well as content hits. Separate messages in one mail store count as separate result identities. Filename discovery finishes independently and can still place a later exact-name match near the top. Live metadata scanning keeps its existing time budget: 500 ms for folder/indexed scopes and 1,500 ms for entire-machine metadata. Reached discovery, display or content-stage limits mean partial coverage, reported as a limited search. An exact match can rank first only if it was discovered within these bounds. Use Open full search for broader supported-scope coverage.

Ranking preserves the literal matching rules above. It adds no automatic acronym expansion, typo correction or usage-history learning. The status and its tooltip retain indexed/live route details, including zero-result fallback notices. OCR content hits include an image, PDF page, or embedded-member region label when available.

Use the Results

  • Down moves from the search box into the results list.
  • Enter opens the selected result from the search box or results list. Focused buttons, scope choices and preview input fields retain their own Enter action.
  • Esc first closes an open scope dropdown or location popup, or stops/closes preview Find. Otherwise it closes the quick window.
  • Ctrl+R reveals the selected result in Explorer.
  • Ctrl+C retains normal text copying in text fields; from the results list it copies the selected result path. Preview controls retain their own local copy actions.
  • Ctrl+P pins the selected result.
  • F4 or Ctrl+I loads an inline preview.

These quick-window action shortcuts can be changed or disabled in File > Settings > Quick Search.

Actions

Each result row has buttons for common actions:

  • Open opens the exact source location when available, otherwise opens the file in its default app, then closes Quick Search.
  • OCR preview opens a dedicated highlighted preview for image, scanned-PDF-page, and embedded-image OCR hits, then closes Quick Search.
  • Reveal opens Explorer with the file selected and closes Quick Search.
  • Copy path copies the full path and closes Quick Search.
  • Pin saves the result to the top of the quick window's pinned list and closes Quick Search.
  • Dragging a result out of the window starts a standard Windows file drag-and-drop operation.

For individual PST/OST messages, Open creates a text-only EML copy in the registered mail application. Inline preview shows the selected message; Copy path and Reveal refer to its store. Store messages cannot be pinned or dragged as physical files. See Mail Results and Preview.

Pinned Results and Preview

An inline database preview adjusts the quick window's minimum height to the visible scope and database controls so records remain readable. Find reserves additional room; closing Find returns to the current database minimum. Closing the preview restores the normal minimum height of 420 and the prior window height if it grew automatically. Manual resizes are preserved.

Indexed SQLite and CSharpDB content hits retain table, row, and column locations. Literal content matching applies within one cell, rather than across columns in a record. File preview uses the same read-only table grid as the main window, including table selection, row paging, Go to row, and Expand. Loading status shows snapshot preparation; Stop loading cancels preparation or page navigation. Another hit in the same unchanged database can reuse the visible preview session. Refresh existing content indexes to add database contents. See Database Search and Preview.

When the search box is empty, Quick Search shows pinned results. Pin frequently used files if you want them available before typing a query.

Press F4 or Ctrl+I to load the selected result's preview. File preview shows images (including WebP, animated GIF, and multipage TIFF), whole PDF pages, spreadsheet grids, ZIP members, complete selected messages, EPUB chapters, OpenDocument and RTF content, formatted Markdown, highlighted source code, or an available installed Windows preview handler. It works for filename-only results and follows your selection while the preview is open. Choose Expand for a larger FileSearch preview window that retains the selected location. PowerToys is not required.

The Matches tab preserves matching lines and nearby context, selected-message previews, and OCR-region highlights. Use the OCR preview action to open the dedicated highlighted region view. See Results and Preview for supported formats, limits, and fallback behavior.

Find in the Loaded Preview

In File preview, choose Find or press Ctrl+F with the preview focused to highlight text in the loaded source/text, formatted HTML view, or embedded text on the displayed PDF page. Enter the complete literal phrase and optionally enable Match case. Words are not split into operators: spaces, quotes, AND, OR, and regex characters are literal. This preview Find is separate from the Quick Search query and works the same way in the main and expanded preview windows.

Use F3 or Match › for the next occurrence and Shift+F3 or ‹ Match for the previous one. In the Find box, Enter starts Find or advances after a search. Esc stops a running Find or closes its panel before Quick Search handles the key. Opening Find gives the preview more room. A database keeps its readable minimum when Find closes. Expand retains the phrase, case setting, and current occurrence when the source content is unchanged.

The status identifies the loaded preview or displayed part being searched, such as one message or chapter. Long text and Markdown previews load the first 250,000 characters; text/source Find retains at most 10,000 occurrences. Truncated previews and reached Find limits declare Partial coverage. An unavailable WebView2 Find feature leaves the ordinary formatted preview usable. See Find Within File Preview for scope, limits, and fallback behavior.

PDF Find searches embedded text on this PDF page while preserving the whole page, crop/rotation alignment, Fit, and zoom. It retains at most 100,000 glyphs, 250,000 page-text characters, and 10,000 occurrences; PDF files remain limited to 100 MB. It does not search other pages or start OCR. A validated existing OCR hit can show its selected line region as a separate outline. Image-only, incompatible, or unavailable embedded text leaves the whole-page preview usable; stale source checks discard the overlays. Expand retains page, Fit/custom zoom, viewing position, and active or closed Find state when the source is unchanged. See PDF Find and OCR Regions.

Use the full FileSearch window for deep search setup, index management, detailed previews, workflows, and reports. Quick Search is optimized for fast lookup and action.

Use PowerToys Command Palette

If you use PowerToys, the separate Command Palette companion offers indexed filename and document-text search with actions to open files or continue a query in FileSearch. Installing it is optional; FileSearch's Quick Search and its shortcuts work independently.
