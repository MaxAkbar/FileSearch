Outlook Mail Search

Find messages in local Outlook files.

Search MSG messages and messages inside PST and OST stores without installing Outlook or an Outlook IFilter. FileSearch reads local files and also supports EML; it does not sign into Exchange or Microsoft 365.

Search a Mail Folder

  1. Close Outlook and choose the folder containing your mail files. A stable copy of a store also works.
  2. Open the search options button, select Contents, and enable Office & PDF text. This option also enables mail extraction.
  3. Search for words in a subject, sender, recipient, body, attachment name, or mail folder. In Unified mode, use type:email invoice to restrict the search to EML, MSG, PST, and OST files.
  4. For repeat searches, add the containing folder with Index > Manage indexed locations, enable document extraction for that location, build its content index, and turn on Use index.
  5. In Quick Search, choose an indexed scope and turn on Content. Enter ordinary search words such as invoice; Quick Search uses plain text rather than Unified field syntax.
The drive file-name index finds the names of mail files. Searching the messages inside them requires a live content search or a folder content index.

What Is Searchable

FormatCoverage
.emlIndividual messages through the existing EML extractor.
.msgSubject, sender, To/Cc recipients, date, plain/HTML/RTF body text, and file attachment names.
.pstMessages and their mail folders, with the same searchable fields as MSG.
.ostMessages present in the local cache, with the same searchable fields as PST. Online-only and unsynchronized mail is unavailable.

MSG/PST/OST extraction does not search attachment contents, embedded messages, or OCR text in mail attachments. It does not export original attachments. Outlook profiles and online mailboxes are not discovered or synchronized automatically.

Search words match the extracted message text. Dedicated from: and subject: operators and message-date filters are not available. File size, created-date, and modified-date filters describe the physical mail file or store.

Results and Preview

Each matching PST/OST message has its own card, including messages with identical subjects. Cards show the subject, sender, date, and mail folder. The preview and Copy file content read only the selected message.

  • Open on a MSG launches its registered application.
  • Open on a PST/OST message creates a text-only EML copy and opens it in the registered mail application. The copy contains readable headers, body text, and attachment names; attachments and original formatting are omitted.
  • Copy path and Reveal in Explorer refer to the containing store.
  • Individual store messages cannot be renamed, deleted, pinned, favorited, or dragged as physical files from result cards.
  • If the store changed after indexing or searching, refresh the index or rerun the search before opening the message. Old message identities are rejected when the store size or modification timestamp changes.

Large Stores and Extraction Limits

Store changes cause the whole changed PST/OST to be extracted again. There is no per-message incremental update yet, so closed, stable copies are useful for large active stores.

  • The default 100 MiB physical-file cap exempts PST/OST. A positive GUI Max size or an explicit CLI --max-size applies to stores too.
  • Default output limits are 2,097,152 characters per message, a 67,108,864-character budget per store including repeated metadata, and 100,000 attempted messages per store, including unreadable messages.
  • MSG property reads and decompressed RTF are limited to 4 MiB. Metadata fields are limited to 4,096 characters, recipient and attachment enumeration is bounded, and store folder nesting is limited to 64 levels.
  • Document-host extraction has a five-minute timeout for stores. Locked, corrupt, or unsupported stores can fail. Truncation and unreadable messages or folders produce extraction warnings; inspect status messages and index failures.

These limits bound emitted text and some reads; they do not guarantee a fixed parser memory limit or support for every historical store variant.

Command Line

.\FileSearch.Cli.exe search "type:email invoice" --path "C:\Mail" --mode unified --json
.\FileSearch.Cli.exe index build "C:\Mail" --json
.\FileSearch.Cli.exe search "type:email invoice" --path "C:\Mail" --mode unified --index --json

JSON and JSON Lines mail hits include optional MailMessage metadata with message identity, subject, sender, recipients, UTC date, mail folder, and store fingerprint. CSV includes mail identity, subject, sender, folder, and date columns. Store hit line numbers are globally unique, and message identities keep results distinct.

Workflow file operations work on physical files, so a copy or move of a matched PST/OST acts on the whole store.

Local Mail Data and Preview Copies

The content index contains searchable mail text and metadata locally under %LocalAppData%\FileSearch\Index. Remove the indexed location to delete its indexed data.

EML preview copies are stored in %TEMP%\FileSearch\MailPreview. Opening another store message attempts to remove FileSearch's own copies older than one day. Copies may remain if another app holds them open or FileSearch is no longer used. Delete that directory manually to clear preview copies immediately.
