Smart Search with ONNX

Search indexed text by meaning.

Smart Search uses a local ONNX embedding model to find related passages even when they use different words. You need a usable model pack and Smart Search vectors for the folder you are searching.

1. Select or Install a Model

Open File > Settings > Smart Search. The Local embedding model list offers BGE small English v1.5 and all-MiniLM-L6-v2; Disabled turns semantic search off.

Selecting a model starts its installation automatically. Install model also starts or retries installation. Wait for the installed model and successful smoke-validation status. Installation downloads model assets; embedding and retrieval then run locally without paid embedding services.

If the selected pack is already on disk, set Model folder to its parent model-packs directory and click Refresh to check it. The default parent is %LocalAppData%\FileSearch\Models. Keep the complete pack, including its vocabulary and any external ONNX weight files.

Have a standalone .onnx file? The current desktop UI selects the two catalog model packs; it has no arbitrary-ONNX import dialog. A bare file is not a complete text embedding setup: it also needs a compatible tokenizer, vocabulary, and model-pack configuration. Model folder is the parent of pack directories, not the path to an ONNX file.

After changing an already-loaded model or its folder, restart FileSearch and any running tray indexer before rebuilding vectors. Model sessions are retained for the lifetime of their process.

2. Build the Folder's Smart Search Index

  1. Open Index > Manage indexed locations and add the folder you want to search.
  2. Build its normal content index. Enable document extraction for Office, PDF, and mail; enable OCR before indexing if you need recognized image text.
  3. Select the location and open its Location details. Under Smart Search, click Rebuild Smart Search.
  4. Allow the background rebuild to finish, then click Refresh status. Look for Smart Search ready and vector coverage for the location.

Rebuild Smart Search creates vectors from existing indexed content without rebuilding the content index. If that content is missing or stale, first use Rebuild selected for the normal index. Installing a model alone does not make unindexed files searchable by meaning.

Vectors must match the selected model. After switching models, rebuild Smart Search for your locations. A drive file-name index supplies names only and cannot supply semantic document or mail content.

3. Run a Semantic Query

  1. Set the folder in the main search bar to the indexed location or a folder inside it.
  2. Open search options, select Contents, choose Unified under Match, and enable Use index.
  3. Enter semantic:"authentication migration" and click Search.
  4. Select a result card to read the cited source passage in the preview pane.
QueryUse
semantic:"authentication migration"Find passages related to a concept, including different wording.
semantic:"termination of an agreement"Find related wording in the indexed folder chosen in the search bar.
semantic:"renewal pricing discussion"Find related indexed mail or document text within the selected folder. Mail content follows the extraction limits.

Use the explicit semantic: form when you want to request meaning-based matching directly. Ordinary search words still perform lexical matching; selecting a model does not make every query semantic. Quick Search uses plain text and does not run semantic: queries.

Understand the Results

Semantic retrieval supplies a ranked selection of related passages. It currently considers up to 25 file candidates and 50 semantic matches before result fusion. This is not an exhaustive count of every relevant passage; use literal, Boolean, or regex searches when you need exact terms.

Combined results can include metadata or lexical candidates too; a displayed item does not necessarily come from vector similarity. Hybrid fusion currently groups candidates by physical file, so semantic results from a PST/OST can show only a selected message from that store.

The semantic provider scopes vectors to the selected search roots, but does not consistently apply Unified type/path/date/size fields or the scan's file filters to semantic candidates. Choose a specific indexed folder to narrow the search and use result facets to refine visible items. Do not rely on a combined type:pdf semantic:... query as a strict file-type restriction.

Local reranker in Settings applies a local heuristic ranking pass after result fusion; it does not install a second ONNX model. Preview the source text to judge whether a match answers your question. Answer creates an extractive draft from visible results rather than generating new facts.

If Smart Search Does Not Work

  • Model missing or not ready: check the selected model, parent model folder, vocabulary, external weights, and installation/validation status. Retry Install model for incomplete packs.
  • No vectors or partial coverage: check the location's Smart Search status. Wait for pending work or use Rebuild Smart Search. A usable model without indexed vectors cannot return semantic matches.
  • Wrong search setup: select Contents, Unified mode, and Use index in the main window. Search inside the indexed location.
  • Changed model or initialization failure: restart FileSearch and any tray indexer, then rebuild vectors with the selected model.
  • Unavailable query chip: the current query parser can label a semantic chip Unavailable even when the model is installed. Check model and vector status; that chip label alone does not confirm runtime availability.
  • CLI query returns no semantic matches: the current CLI search process does not load the GUI's selected model configuration. The desktop main window is the documented Smart Search entry point.

Local Storage

Model assets are kept in the configured model folder. Semantic vectors are stored beside the content database in %LocalAppData%\FileSearch\Index\filesearch.vectors.json and filesearch.vectors.segments. Selecting Disabled stops semantic search; model and index files remain on disk.
